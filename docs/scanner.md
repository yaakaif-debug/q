# Сканер, теневой портфель и производные данные (M1)

Этот документ описывает, что делает M1 и как оператор проверяет его на своём
сервере. Claude Code приёмочные тесты не запускал (SPEC.md, «Testing responsibility»).

## Что считает сканер

Раз в `scanner.interval_secs` (по умолчанию 60 с) сканер оценивает каждую пару
инструментов одного базового актива на разных площадках из `config/symbols.toml`.
Пара из двух дексов Hyperliquid (ядро и HIP-3 или два HIP-3) — это S2, остальные — S1.

1. **Фандинг к APR.** `APR = r · 8760 / h`, где `h` — интервал площадки: Aster —
   `fundingInfo`, Hyperliquid ядро — `predictedFundings`, HIP-3 и Lighter — выводится
   по отметкам расчётов. Ничего не захардкожено.
2. **Направление.** Коротко там, где фандинг выше (по прогнозу, при его отсутствии — по EMA).
3. **Три оценки спреда** `s = APR_short − APR_long`: по текущему прогнозу, EMA расчётных
   ставок за 24 ч (`α = 2 / (n + 1)`, `n` — число интервалов в окне), реализованное среднее
   за 7 дней (сумма ставок × 8760 / покрытые часы; для молодой истории — покрытые часы, а
   не 168).
4. **Устойчивость знака.** Ряд спреда строится в моменты расчётов ноги с более длинным
   интервалом; знак должен держаться последние `k_settlements` (по умолчанию 6) расчётов.
5. **Допуск пары.** Обе ноги активны; ОИ ≥ `risk.min_oi_usd` на каждой; возраст листинга
   ≥ `risk.min_listing_age_h` (Aster и Lighter сообщают дату листинга, для Hyperliquid
   берётся время первого появления в базе); маркировки расходятся не больше
   `risk.max_mark_divergence_pct` (иначе это, скорее всего, разные базовые активы).
   Исключения задаются в `symbols.toml` (`allow_mark_divergence`, `allow_new_listing`).
6. **Издержки входа и выхода** на ступенях `notional_tiers_usd` и на рассчитанном размере:
   комиссии обеих ног на уровне аккаунта, проскальзывание по стакану от mid, на выходе —
   с множителем `costs.unwind_spread_multiplier` («ожидаемый спред при разворачивании»),
   доля переводов на перебалансировку (`costs.rebalance_usd_s1`, для S2 —
   `rebalance_usd_s2`), конвертация обеспечения на споте HL для дексов не на USDC.
   При `costs.maker_first = true` нога с меньшей мейкер-комиссией считается мейкером:
   мейкер-комиссия и без проскальзывания; вторая нога — тейкер с проходом по стакану.
7. **Экономика.** `s_net = s_ema − cost · 8760 / (N · H_exp)`, точка безубыточности
   `H_be = cost · 8760 / (N · s_ema)`, `C = (N / L_a + N / L_b) / (1 − r)`,
   `ROC = s_net · N / C`, нужный чистый спред для целевого ROC — `target · C / N`.
8. **Размер.** Минимум из капитала пары, 1% меньшего ОИ, 25% глубины в 10 bp от mid на
   более тонкой стороне и остатка лимитов платформ; количество округляется вниз до общего
   кратного лотов обеих площадок.
9. **Вход разрешён**, если все три оценки ≥ `min_gross_apr`, знак устойчив, `H_be ≤
   max_breakeven_hours`, `s_net ≥ min_net_apr` (S2 — свой `min_net_apr`), до ближайшей
   выплаты получающей ноге не дольше ожидаемого удержания, а для S2 — до ближайшей смены
   сессии базового актива не меньше `session_guard_min`.

Результат каждой оценки — `reports/scan-latest.csv` (перезаписывается атомарно) и метрика
`s_net_apr{pair}` для пар, в которые разрешён вход.

## Теневой портфель

Теневой портфель распределяет `scanner.shadow_capital_usd` (по умолчанию $100k) по тем же
правилам, что будут у стратегий S1/S2 в M2, но без ордеров:

- **Вход** — лучшие по `s_net` пары с разрешённым входом; капитал пары не больше
  `max_pair_share_pct` капитала и свободного остатка; S2 вместе — не больше
  `max_s2_share_pct`; маржа на платформе — не больше `max_platform_share_pct`; один
  инструмент не участвует в двух парах. Комиссии, проскальзывание, перевод и половина
  конвертации списываются по стаканам в момент входа.
- **Фандинг** начисляется в моменты фактических расчётов площадок, только позициям, открытым
  до расчёта: `±ставка × количество × цена расчёта` (Hyperliquid — оракул, Lighter — индекс,
  Aster — маркировка, UNVERIFIED для Aster).
- **Выход** — EMA спреда в ориентации позиции ниже `exit_apr` на `m_intervals` расчётах
  подряд, нога неактивна или делистингована, превышена `max_drawdown_pct`. Издержки выхода —
  по стаканам в момент выхода; базисный результат реализуется.
- **Дневной лимит убытка** блокирует новые входы на сутки.
- Состояние сохраняется в SQLite (`database.path`) после каждой оценки и при остановке;
  журнал (фандинг, комиссии, проскальзывание, переводы, базис) — построчно.

Дневной отчёт за сутки UTC пишется в `reports/<YYYY-MM-DD>.md`,
`<YYYY-MM-DD>-positions.csv` и `<YYYY-MM-DD>-opportunities.csv`; при
`scanner.telegram_summary = true` и настроенном Telegram отправляется короткая сводка.
Критерий приёмки M1 (SPEC.md): 30-дневный отчёт, переход к M2 только при теневом ROC
≥ 10% годовых и просадке меньше 2%.

## Сопоставление символов

Сканер торгует только пары из `config/symbols.toml`. Совпадения по базовому активу на двух
и более площадках, ещё не сопоставленные, сканер раз в сутки пишет в
`config/symbols.suggested.toml`. Оператор проверяет, что инструменты на один и тот же
базовый актив (размер контракта, индекс, оракул), и переносит одобренные записи вручную.
Масштабированные контракты (`1000PEPE`) намеренно не совпадают с базовыми.

Календари сессий (`[calendars]` в `symbols.toml`) задаются в UTC; переход на летнее время
оператор учитывает сам — в зависимостях нет базы часовых поясов.

## Повтор по записям

```bash
./target/release/spread-hunter scan --replay data/raw --from 2026-11-01 --to 2026-11-08 --out reports/replay
```

Повтор читает сырые записи всех площадок, сливает их по времени получения, разбирает теми же
парсерами, что и живые адаптеры, и прогоняет тот же движок сканера с теневым портфелем.
Время берётся из записей, поэтому результат детерминирован.

## Производные Parquet

```bash
./target/release/spread-hunter derive --raw data/raw --out data/parquet --date 2026-11-01
```

Без `--date` — вчерашние сутки UTC (так запускает таймер `spread-hunter-derive.timer`).
Таблицы в `data/parquet/<YYYY-MM-DD>/`:

| Файл | Содержимое |
| --- | --- |
| `bbo_1s.parquet` | BBO на конец каждой секунды, в которую он менялся: `ts_s, venue, symbol, bid, bid_qty, ask, ask_qty` |
| `funding.parquet` | Изменения прогноза и расчёты: `ts_ms, venue, symbol, kind, rate, interval_h, next_ms` |
| `book_snapshots.parquet` | 20 уровней каждой стороны раз в минуту: `ts_s, venue, symbol, side, level, px, qty` |
| `oi.parquet` | ОИ и маркировка раз в минуту: `ts_s, venue, symbol, oi_base, oi_usd, mark` |

Числа в Parquet — `f64`: это аналитика, не денежный путь.

## UNVERIFIED в M1

- Цена, по которой Aster считает платёж фандинга (принята маркировка).
- Стоимость переводов для перебалансировки S1 (`costs.rebalance_usd_s1 = 4`) и конвертации
  стейблкоинов на споте HL (`costs.collateral_conversion_bps = 2`).
- Комиссии Aster уровня аккаунта (публично недоступны; в конфиге 0% / 0.04% из SPEC.md).
- Время смены сессий для акций на каждом HIP-3 дексе и на Lighter/Aster.
- Модель мейкер-ноги без проскальзывания в сканере — оптимистична для тонких стаканов;
  исполнение и очередь моделируются в M2 (`sh-sim`).
