# Исполнение, риск, paper, selftest (M2)

Этот документ описывает код M2 и то, как оператор проверяет его на своём сервере.
Claude Code приёмочные, testnet- и live-тесты не запускал и ордеров не ставил
(SPEC.md, «Testing responsibility»): всё ниже проверено только офлайн — модульными,
property-тестами и учениями на симуляторе площадок.

## Архитектура

Один синхронный движок (`src/engine.rs`) владеет всем изменяемым состоянием:
рынком, стратегиями, риском, задачами исполнения, ордерами и книгой позиций. Входы —
события рынка, ответы и события исполнения, такты времени и команды оператора;
выходы — команды площадкам, оповещения, записи журнала. Движок не делает I/O и не читает
часы, поэтому один и тот же код работает в трёх оболочках:

| Режим | Данные | Исполнение | Оболочка |
| --- | --- | --- | --- |
| `paper` | живые адаптеры | симулятор `sh-sim` | `src/trade.rs` |
| `backtest` | сырые записи через парсеры адаптеров | симулятор `sh-sim` | `src/backtest.rs`, бинарник `backtest` |
| `live` (M3) | живые адаптеры | приватные адаптеры (`Execution`) | M3 |

Крейты M2:

| Крейт | Содержимое |
| --- | --- |
| `sh-venue-api::exec` | Трейт `Execution`, ордера, заполнения, позиции, балансы, клиентские ID, команды и результаты |
| `sh-sim` | Симулятор площадок: тейкер по стакану с задержкой, мейкер по очереди, фандинг, режимы отказа |
| `sh-exec` | Автомат состояний ордера (`OrderTracker`) и задача пары S5 (`PairJob`) |
| `sh-risk` | Проверки перед входом и ордером, мониторы, kill switch |
| `sh-strategy` | Трейт `Strategy`, S1 и S2 (перенос фандинга) |
| `sh-portfolio::book` | Пары и их жизненный цикл, позиции по заполнениям, сверка, атрибуция PnL |
| `sh-venue-*::exec` | Приватные адаптеры Hyperliquid, Lighter (FFI), Aster |

## Ордера

- Каждый ордер несёт клиентский ID: Hyperliquid `cloid` (128 бит hex), Lighter
  `client_order_index` (≤ 2^48 − 1), Aster `newClientOrderId` (`sh-<число>`). Генератор —
  миллисекунды × 1000 + счётчик: уникален в сессии и между перезапусками.
- Состояния: `New`, `Sent`, `Acked`, `PartiallyFilled`, `Filled`, `Cancelled`, `Rejected`,
  `Expired`, `Unknown`. Применяются только переходы, подтверждённые ответом или событием
  площадки; конечные состояния не меняются (property-тест).
- Тайм-аут ответа → `Unknown` → запрос по клиентскому ID раз в секунду. Ордер никогда не
  отправляется повторно вслепую. Если площадка не знает ордер и через 10 с — он не дошёл.
- После перезапуска все живые ордера из сохранённого состояния переводятся в `Unknown` и
  уточняются запросом.
- Количество исполненного считается по заполнениям (дедупликация по ID сделки), статус — по
  площадке; расхождение ловит сверка позиций.

## S5: мейкер-первый вход (задача пары)

1. Мейкер-нога — с меньшей мейкер-комиссией (при равенстве — короткая).
2. Объём режется на дочерние ордера не больше `child_usd` (кратно общему лоту обеих ног).
3. Дочерний post-only стоит по BBO хедж-площадки минус тейкер-комиссия хеджа, ожидаемое
   проскальзывание и `edge_bps`; если цена пересекла бы стакан мейкер-площадки, ордер
   встаёт в лучший уровень своей стороны. Перестановка — при сдвиге больше `reprice_bps`.
4. На каждое заполнение — IOC на хедж-площадке на заполненный объём (кратно лоту хеджа),
   предел BBO ± `max_slip_bps`.
5. Хедж не исполнен за `hedge_timeout_ms` — повтор с пределом `max_slip_bps × (попытка+1)`
   до `hedge_retries`; дальше непохеджированный объём закрывается reduce-only IOC на
   мейкер-площадке, пара — `Unwinding`, оповещение CRIT.
6. Пока непохеджированный номинал книги ≥ `max_unhedged_usd`, новые дочерние не ставятся.

Выход — та же последовательность в обратную сторону, все ордера reduce-only. Сброс
(`kill --flatten`, ADL) — обе ноги IOC reduce-only срезами `child_usd`, хедж за каждым
срезом. Остаток меньше лота журналируется, не форсируется; непарный остаток после выхода
закрывается отдельным reduce-only IOC.

Свойство из тестов: при любых объёмах сделок непохеджированный объём задачи не больше
одного дочернего ордера, а итог входа нейтрален по дельте.

## Риск

| Проверка | Где | Действие |
| --- | --- | --- |
| Доли платформ, S2, пары; плечо ноги | перед входом | вето |
| `trading_enabled` площадки | перед входом и ордером | вето (в paper/backtest — все включены) |
| Дневной убыток | монитор | входы запрещены на 24 ч, CRIT |
| Просадка от пика | монитор | все пары в выход, CRIT |
| Непохеджированный номинал | монитор и ордер | новые дочерние не ставятся |
| Чистая дельта сверх непохеджированного | монитор | остатки закрываются reduce-only, CRIT |
| Расстояние до ликвидации | монитор (цена ликвидации — из снимков площадки) | CRIT; ниже половины порога — выход из пары |
| Устаревшие данные `md_stale_ms`, приватный поток упал | монитор | площадка деградировала: нет новых ордеров на ней; CRIT при открытых позициях |
| Отвязка стейблкоина | по курсу обеспечения | входы на этом обеспечении запрещены |
| Расхождение сверки (2 проверки подряд) | каждые `reconcile_every_s` | `Halted`: отмена ордеров, ничего нового |
| Изменение метаданных удерживаемой пары (статус, плечо, лот) | на событии метаданных | WARN; делистинг или снижение плеча — выход |
| Заполнение не по нашему ордеру (ADL, ликвидация) | на событии | CRIT, сброс пары |

Ордера reduce-only проходят всегда (кроме выключенной торговли на площадке): это путь к
безопасности. Старт: до первой успешной сверки по всем торгуемым площадкам стратегии
не входят.

## Kill switch

Три пути, одно действие — отмена всех ордеров и запрет новых:

```bash
./target/release/spread-ctl kill
```

```bash
touch run/KILL
```

В Telegram от пользователя из `allowed_user_ids`: `/kill`. Вариант со сбросом позиций:
`spread-ctl kill --flatten`, файл `run/KILL` с содержимым `flatten` или `/kill flatten`.
Без сброса входы с непохеджированным объёмом разворачиваются reduce-only на мейкер-ноге.
Снять: `spread-ctl release-kill` (файл `run/KILL` удалить заранее).

## Режим paper

`engine.mode = "paper"` (значение по умолчанию). Живые данные со всех площадок,
исполнение — симулятор с моделью бэктеста, полная запись состояния в SQLite
(`engine_state`), журнал PnL, оповещения, `spread-ctl`, kill switch. Капитал и RTT
симулятора — `[paper]` в конфиге (RTT подставьте из отчёта `latency-probe`). После
перезапуска позиции симулятора восстанавливаются из книги, затем сверка их подтверждает.

Ограничения модели: свои ордера не меняют записанный стакан; мейкер-ордер исполняется
только сделками сквозь его цену после очереди, стоявшей на уровне при постановке;
HIP-3 дексы в симуляции берут маржу из общего капитала Hyperliquid (переводы между
дексами не моделируются).

## spread-ctl

```bash
./target/release/spread-ctl status
```

Команды: `status`, `kill [--flatten]`, `release-kill`, `resume` (снять `Halted`), `pause`,
`unpause`, `exit <pair>`, `adopt <exchange>` (принять позиции площадки как истину после
ручного разбора расхождения). Сокет — `control.socket` (права 600). Горячая перезагрузка
порогов (`spread-ctl reload`) не сделана: пороги меняются перезапуском (см. PROGRESS.md).

## Бэктест

```bash
./target/release/backtest --replay data/raw --from 2026-11-01 --to 2026-11-08 --out reports/backtest
```

Сырые записи → парсеры адаптеров → движок (стратегии, риск, S5) → симулятор. Результаты:
`ledger.csv`, `final-status.json`, `alerts.log`, дневные отчёты. Случайности нет: одни и те
же данные дают побайтно одинаковый результат (тест `replay_e2e`).

## selftest

Пишет и проверяет офлайн Claude Code; запускает только оператор. Ставит реальные ордера
(малого размера) и проверяет на каждой площадке: метаданные, балансы, post-only + отмену,
IOC-заполнение, заполнение в приватном потоке, позицию, запрос по клиентскому ID,
закрытие reduce-only, чтение платежей фандинга, перевод $1 между дексами HIP-3 и обратно
(Hyperliquid, `--transfer-dex`), отмену всех ордеров (kill switch) и что аккаунт остался
без позиции. Печатает таблицу PASS/FAIL/SKIP и сохраняет её в `reports/selftest-*.md`.

```bash
./target/release/spread-hunter selftest --network testnet --max-notional-usd 20
```

```bash
./target/release/spread-hunter selftest --network mainnet --max-notional-usd 15 --venue hyperliquid --transfer-dex xyz --i-understand-real-money
```

Ограничения: номинал ордера не больше $1000; mainnet требует
`--i-understand-real-money`; символы по умолчанию — `BTC` (Hyperliquid), `ETH` (Lighter),
`BTCUSDT` (Aster), меняются флагами `--symbol-*`. Номинал должен быть не меньше минимального
ордера площадки (Hyperliquid — $10). selftest не зависит от `engine.mode` и
`trading_enabled`: это отдельный инструмент оператора.

## Учения (офлайн, `tests/engine_drills.rs`)

| Учение | Что проверяется |
| --- | --- |
| Вход S1 | мейкер — Aster (0%), все дочерние post-only, ноги равны, книга совпадает с площадкой |
| Kill switch | живые ордера отменены, новых нет; со сбросом — обе ноги закрыты reduce-only |
| Отказ площадки | данные хедж-площадки устарели → деградация, мейкер-ордер снят; восстановление |
| Делистинг HIP-3 | событие метаданных → WARN и выход, пара закрыта |
| ADL | заполнение не по нашему ордеру → CRIT, вторая нога сокращена, пара закрыта |
| Сверка | позиция площадки изменилась без событий → `Halted`, новых ордеров нет |
| Перезапуск | состояние из JSON, симулятор из книги, сверка проходит |
